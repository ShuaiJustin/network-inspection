# GitHub 发布与软件内更新设计

日期：2026-10-21

## 已确认需求

软件使用 Tauri 2 官方 updater 插件实现检查、下载、签名验证与安装，GitHub Releases 保存安装包和更新清单。当前版本保持 0.1.32，下一次正式发布递增版本。目标仓库地址尚需用户提供；如需新建仓库，由用户指定归属、名称和可见性。

## 软件行为

启动后后台检查正式版本；系统设置提供手动检查入口。发现新版后展示版本、更新说明，让用户决定是否下载。展示下载进度，下载失败允许重试，检查失败不影响巡检和登录。下载后由官方插件验证签名，验证失败禁止安装。

安装前再次确认；存在执行中的巡检时暂缓安装，提示结束任务后重试。安装前停止本地 API 子进程，通过官方 Windows 安装流程退出并安装，保留现有用户数据。开发浏览器环境不尝试运行桌面插件。仅允许安装更高版本。

## 发布与配置

统一管理 Cargo、Tauri 和前端的应用版本，发布前检查一致性。提供 PowerShell 发布流程，先构建 Python sidecar，再构建 Windows NSIS/MSI 安装包，生成签名及 latest.json，上传到对应 v版本号 Release。更新清单包含版本、说明、发布时间、Windows 架构的安装包地址和签名。默认检查公开仓库最新正式 Release 中的 latest.json；不将 GitHub 访问令牌打包进软件。

更新签名私钥保存在仓库外；公钥写入应用配置。GitHub 登录通过账号授权完成，私钥、凭据、运行数据库、构建缓存不提交。首次上传前补齐忽略规则并检查待提交文件，尤其是设计参考目录中的 node_modules 和本地设备数据。

## 验证

测试无更新、发现新版、网络失败、下载失败与重试、重复检查、签名失败、任务执行中禁止安装。运行前端测试和生产构建、Rust 检查以及发布清单验证。真实更新验收需要 GitHub 账号连接、已创建仓库和两个递增版本的已签名安装包；未完成真实安装升级时明确标注。

## 当前外部依赖

GitHub 连接器返回 USER_NOT_LOGGED_IN，账号尚未连接；本地未配置远程仓库，本机未发现 GitHub CLI。仓库名称和可见性尚未确认。本地已有设计文档提交，其余项目文件尚未提交。GitHub 上传需先完成账号连接并确定仓库；本地实现和测试可独立进行。
